# 03 — المعمارية التقنية (Flutter + شبكة محلية LAN)

## 1. القرار المعتمد
- **Flutter + Dart:** كود واحد لتطبيق أندرويد + تطبيق ويندوز.
- **سيرفر LAN:** جهاز الكمبيوتر الرئيسي في المطبعة يعمل كسيرفر، وبقية الأجهزة تتصل به عبر IP ثابت.
- **قاعدة بيانات مركزية** على السيرفر + تخزين مؤقت (Cache) على كل جهاز.

## 2. مخطط المعمارية

```
 [تطبيق ويندوز Flutter] ──┐
                          ├─── HTTP/REST (JSON) ─── [سيرفر LAN: API]
 [موبايل أندرويد 1] ──────┤        192.168.1.100:8000        │
 [موبايل أندرويد 2] ──────┘                                  ├── [قاعدة البيانات]
                                                             └── [مجلد النسخ الاحتياطي + ملفات PDF]
```

## 3. المكدس التقني المقترح (موصى به)

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| تطبيقات | Flutter 3.x + Dart + Riverpod/Bloc | كود واحد، عربي RTL ممتاز، أداء عالٍ |
| التخزين المحلي | Drift / Isar + SharedPreferences | عمل مؤقت عند انقطاع الشبكة |
| سيرفر API | Python FastAPI | سهل، سريع، توثيق تلقائي، عربي |
| قاعدة البيانات | PostgreSQL (أو SQLite للبداية) | موثوقة، نسخ احتياطي سهل |
| التقارير/PDF | Dart pdf + printing | طباعة العروض والأوامر والسندات |
| الشبكة | REST + WebSocket للتنبيهات | تحديث الحالات لحظياً |
| النشر | ملف exe محمول + APK | تثبيت بسيط بدون متجر |

بدائل مقبولة: السيرفر بـ Node.js (NestJS) أو C# (ASP.NET Core) إذا توفر مبرمج بتلك الخبرة — الواجهات (API) تبقى نفسها.

## 4. إعداد الشبكة المحلية

1. تثبيت IP ثابت للسيرفر، مثال: `192.168.1.100`.
2. تشغيل خدمة الـ API على المنفذ `8000` + خدمة قاعدة البيانات.
3. فتح الجدار الناري (Firewall) للمنفذ `8000` داخل الشبكة فقط.
4. في كل تطبيق (أندرويد/ويندوز): شاشة إعدادات "عنوان السيرفر" + زر "اختبار الاتصال".
5. اسم بديل سهل (اختياري): `http://matbaa-server:8000` عبر mDNS.
6. السيرفر يعمل تلقائياً مع إقلاع ويندوز (Windows Service / Task Scheduler).

## 5. المزامنة وعدم الاتصال (Offline-first مبسط)

- عمليات القراءة: من الكاش المحلي أولاً ثم تحديث من السيرفر.
- عمليات الكتابة (عرض/أمر/حركة/دفعة): تُرسل للسيرفر مباشرة، وإذا تعذر الاتصال تُحفظ في "صندوق الصادر" وتُزامن تلقائياً عند عودة الشبكة.
- أرقام المستندات (عرض/أمر/حركة) تُولد من السيرفر فقط لمنع التكرار — عند عدم الاتصال تُحجز أرقام مؤقتة ثم تُستبدل.

## 6. الأمان في LAN

- حسابات + كلمات مرور مشفرة (bcrypt) + توكن JWT قصير المدة.
- صلاحيات على مستوى API وليس فقط الواجهة.
- السيرفر لا يُكشف على الإنترنت (يستمع على LAN فقط).
- نسخة احتياطية يومية: نسخة على السيرفر + نسخة على فلاش/USB أسبوعياً.
- سجل تدقيق `audit_log`: (المستخدم، العملية، الجدول، المعرف، الوقت، القيم قبل/بعد).

## 7. هيكل مستودع الكود المقترح

```
matbaa-erp/
├── apps/
│   ├── mobile/            # Flutter Android
│   └── desktop/           # Flutter Windows (نفس الكود مع تخصيص نوافذ)
├── packages/
│   ├── core/              # المنطق المشترك: الموديلات + محرك التسعير + الأدوات
│   └── api_client/        # الاتصال بالسيرفر
├── server/
│   ├── app/               # FastAPI: routers, models, services
│   ├── migrations/
│   └── docker-compose.yml
└── docs/                  # هذا التوثيق
```

- محرك التسعير يُكتب مرة واحدة في `packages/core/pricing.dart` ويُستخدم في الموبايل والديسكتوب، ويُعاد تنفيذه في السيرفر للتحقق (نفس المعادلات).

## 8. بيئات التشغيل

| البيئة | الوصف |
|--------|-------|
| dev | على جهاز المبرمج: سيرفر محلي + Flutter debug |
| prod-lan | سيرفر المطبعة + تطبيقات الإصدار (release) |

## 9. قرارات تحتاج تأكيدك لاحقاً
- PostgreSQL أم SQLite للبداية؟ (التوصية: ابدأ SQLite لتقليل التعقيد، وانتقل لـ PostgreSQL عند تعدد المستخدمين.)
- هل يوجد طابعة شبكة أم USB؟ (يؤثر على إعداد الطباعة من الموبايل.)
